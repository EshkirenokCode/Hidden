# Удобство и защита окна — 4 ноября 2026

Проверена и доработана версия 0.3 на текущем Mac (macOS 26.6.2, Electron 45.2.1). Оценка относится к конкретным проверенным сценариям, а не к полному соответствию Ghost GPT.

## Найденные проблемы и исправления

| Проблема | Изменение |
|---|---|
| Компактный виджет скрывал вопрос, снимок и историю | Все основные кнопки доступны в компактном окне; ввод вопроса и просмотр снимка не требуют разворачивания |
| Компактное окно оставалось за другими приложениями | Компактный режим автоматически закрепляется поверх окон; при возврате восстанавливается прежний режим закрепления |
| Новая аудиоподсказка сбивала чтение истории | Старый ответ остаётся на месте, показывается число новых ответов и кнопка перехода к свежему |
| Выбор истории затирал набранный вопрос | Просмотр ответа отделён от поля ввода; черновик сохраняется |
| В виджете нельзя было переключать ответы | Назад/вперёд, счётчик, Cmd/Ctrl+Shift+Left/Right; переключение блокируется на время ручной генерации |
| Код выглядел как обычный текст | Закрытые блоки тройных кавычек отображаются отдельными моноширинными блоками с горизонтальной прокруткой; HTML не исполняется |
| При обновлении потокового ответа сбрасывалась позиция чтения | Прокрутка сохраняется, если пользователь ушёл от конца ответа |
| Обычное скрытие не останавливало отправку аудио | Отдельная кнопка «Скрыть и остановить» и Cmd/Ctrl+Shift+Escape: отмена запросов, прекращение аудиозахвата и скрытие окна. Обычное скрытие сохраняет сессию |
| Конфликты части горячих клавиш были незаметны | Проверяется регистрация каждого сочетания, занятые перечисляются в интерфейсе; кнопки остаются доступны |
| Ограничения защиты были спрятаны в раскрывающемся блоке | Статус защиты и ограничение macOS видны постоянно, включая компактный режим |

## Проверка фактического захвата Chrome

1. Запущена локальная страница `tools/capture-check.cjs` на 127.0.0.1. В ней используется настоящий `navigator.mediaDevices.getDisplayMedia`, без аудио.
2. В нативном диалоге Chrome выбран «Весь экран». Это локальный видеопредпросмотр: данные не отправляются, запись на диск не ведётся.
3. Окно Ghost переведено в компактный режим, автоматически закреплено поверх окон, наполнено демонстрационным ответом и поднято через accessibility Raise.
4. Отдельно запущено **незащищённое** окно `tools/capture-control.cjs` с ярким маркером CONTROL VISIBLE. Оно появилось в потоке Chrome; содержимое защищённого окна Ghost в этом потоке не появилось. Это позволяет отличить работающий поток от отсутствия/зависания захвата.
5. Предпросмотр проверен визуально, затем захват остановлен. Контрольное окно закрыто.

**Результат: содержимое Ghost не показано в проверенном режиме захвата всего экрана Chrome на этом Mac.** Это не доказательство исключения из списка выбора окон, системных индикаторов, всех API захвата или всех программ. Zoom, Meet, Teams, Windows и Linux в этом запуске отдельно не тестировались. Даже в другом режиме Chrome результат может отличаться.

Electron документирует, что macOS ScreenCaptureKit может захватывать защищённые окна: [официальная документация](https://www.electronjs.org/docs/latest/api/browser-window#winsetcontentprotectionenable-macos-windows). Поэтому интерфейс не обещает универсальную невидимость. Подтверждение необходимо на стороне зрителя в конкретной программе.

## Автоматические проверки

10 unit-тестов и расширенный smoke-тест настоящего Electron проходят. Smoke использует искусственный микрофон и подменённый API; проверяет:

- потоковый ответ, конфигурацию, изоляцию ключей и renderer;
- просмотр истории без потери черновика, сохранение читаемого ответа при новой аудиоподсказке и переход к свежему;
- доступность поля ввода и кнопок в компактном режиме, закрепление и восстановление прежнего режима;
- начало/остановку аудио и экстренное скрытие с остановкой;
- флаг защиты, скрытие/возврат окна и снимок-предпросмотр.

Скриншоты внутренних проверок: `artifacts/smoke.png`, `artifacts/compact.png`. Они создаются из renderer специально для проверки макета и не являются внешним захватом экрана.

В этом аудите облачный API не вызывался и старый временный ключ не использовался. Скорость и качество распознавания в реальном разговоре этим аудитом не измерялись.
